**关键设计模式应用**:

#### (a) 状态模式 — RuntimeStatus 状态切换
```typescript
// src/domain/runtime-phase.ts
export interface RuntimePhase {
  readonly name: string
  enter(ctx: PhaseContext): void
  exit(ctx: PhaseContext): void
  canTransitionTo(target: string): boolean
}

export class IdlePhase implements RuntimePhase {
  name = "idle"
  enter(ctx: PhaseContext): void { /* 重置计数器 */ }
  exit(ctx: PhaseContext): void { /* 持久化 */ }
  canTransitionTo(target: string): boolean {
    return ["collecting", "session_shutdown"].includes(target)
  }
}

export class CollectingPhase implements RuntimePhase {
  name = "collecting"
  enter(ctx: PhaseContext): void { /* 初始化收集器列表 */ }
  exit(ctx: PhaseContext): void { /* 汇总节点数 */ }
  canTransitionTo(target: string): boolean {
    return ["prioritizing", "error"].includes(target)
  }
}
// ... 其他阶段类似

export class RuntimeStateMachine {
  private phase: RuntimePhase
  private phases = new Map<string, RuntimePhase>()

  registerPhase(phase: RuntimePhase): void { this.phases.set(phase.name, phase) }

  transition(target: string, ctx: PhaseContext): void {
    const next = this.phases.get(target)
    if (!next) throw new Error(`Unknown phase: ${target}`)
    if (!this.phase.canTransitionTo(target)) {
      throw new Error(`Invalid transition: ${this.phase.name} → ${target}`)
    }
    this.phase.exit(ctx)
    this.phase = next
    this.phase.enter(ctx)
  }
}
```

#### (c) 策略模式 — 降级策略
```typescript
// src/application/degradation-strategies.ts
// scheduler.ts 中的 switch-case 重构为策略模式

export interface DegradationStrategy {
  readonly name: string
  apply(node: PromptNode, remainingBudget: number): DegradationResult | null
}

export class DropStrategy implements DegradationStrategy {
  name = "drop"
  apply(_node: PromptNode, _remaining: number): null { return null }
}

export class TruncateStrategy implements DegradationStrategy {
  name = "truncate"
  apply(node: PromptNode, remaining: number): DegradationResult | null {
    const ratio = remaining / node.byteSize
    const truncated = node.content.slice(0, Math.floor(node.content.length * ratio))
    return {
      node: { ...node, content: truncated, byteSize: new TextEncoder().encode(truncated).byteLength },

    }
  }

strategies.set("compress", new CompressStrategy())
strategies.set("summarize", new SummarizeStrategy())
```

## 6. 会话存储项目级化（2026-06-05）

### 背景

原架构将 session 存储在全局目录 `~/.pi/agent/sessions/<encoded-cwd>/` 中，与 Pi 系统耦合。存在以下问题：

1. **跨项目污染**：所有项目的 session 混在同一层级目录
2. **耦合 PI 全局状态**：依赖 `~/.pi/agent/sessions` 目录结构
3. **数据迁移困难**：项目移动后 session 丢失
4. **双存储并存**：StateStore 用本地 `.json` 文件，Pi JSONL 用全局目录，两套互不相同

### 变更内容

将 session 存储从全局目录迁移到项目级目录：

```
旧: ~/.pi/agent/sessions/--F-zhao-pi rp--/<timestamp>_<uuid>.jsonl
新: <projectRoot>/.pi/sessions/--F-zhao-pi rp--/<timestamp>_<uuid>.jsonl
```

### 修改的文件

| 文件 | 变更 |
|------|------|
| `src/infrastructure/pi-jsonl-storage.ts` | 重写 — 构造函数接收 `projectRoot`，实现完整 StorageProvider 接口，JSONL 读写 + 树形重建 + 会话扫描 |
| `src/infrastructure/pi-jsonl-writer.ts` | 所有函数新增 `projectRoot` 参数，目录切换为项目级 |
| `src/composition-root.ts` | 注入链路：`FileSystemStorage` → `PiJsonlStorage(cwd)` |
| `src/presentation/http/routes/route-context.ts` | 新增 `projectRoot` 字段 |
| `src/server.ts` | RouteContext 传入 `process.cwd()` |
| `src/presentation/http/routes/session-routes.ts` | `initJsonlFile` / `rebuildHistoryFromJsonl` 传递 `projectRoot` |
| `src/presentation/http/routes/turn-routes.ts` | `appendMessageToJsonl` 传递 `projectRoot` |
| `src/rp-web-server.ts` | 新增 `projectRoot` 参数，统一 `encodeCwd` 函数，移除 `homedir` 依赖 |
| `.pi/extensions/rp-engine/index.ts` | `createRPWebServer` 传入 `process.cwd()` |
| `scripts/migrate-sessions.mjs` | 新文件 — 全局目录 → 项目目录一次性迁移 |
| `package.json` | 新增 `"migrate-sessions"` script |

### 架构变化

```
旧架构（双存储互不相同）:
StateStore ──► FileSystemStorage ──► sessions/*.json（本地）
pi-jsonl-writer ──► ~/.pi/agent/sessions/<encoded>/*.jsonl（全局）
rp-web-server scanSessions() ──► ~/.pi/agent/sessions/<encoded>/*.jsonl

新架构（统一到项目级 PiJsonlStorage）:
StateStore ──► PiJsonlStorage ──► .pi/sessions/<encoded>/*.jsonl（项目级）
pi-jsonl-writer ──► .pi/sessions/<encoded>/*.jsonl（同上）
rp-web-server scanSessions() ──► .pi/sessions/<encoded>/*.jsonl（同上）
```

### 关键设计决策

1. **PiJsonlStorage 实现完整 StorageProvider 接口**：`read()` 从 JSONL 重建 JSON 快照，`write()` 首次完整写入 / 后续增量同步，`list()` 扫描 `.jsonl` 文件
2. **增量同步策略**：`write()` 首次调用完整写入，后续调用对比内存 history 与文件已有消息，仅追加增量，避免消息重复
3. **统一 encodePath 函数**：修复了原先 `pi-jsonl-storage` 和 `rp-web-server` 中两个不同编码实现导致的目录名不一致 bug
4. **保持子目录隔离**：`<projectRoot>/.pi/sessions/<encodePath(cwd)>/` 确保同一项目从不同子目录运行时 session 隔离
5. **向后兼容**：提供 `npm run migrate-sessions` 命令，自动检测新旧两种编码格式，将全局目录的 `.jsonl` 文件复制到项目目录

### 迁移命令

```bash
# 安装后首次运行
npm run migrate-sessions
```

该命令会：
- 自动检测 `~/.pi/agent/sessions/` 下是否存在当前项目的会话
- 支持两种旧编码格式自动识别
- 复制所有 `.jsonl` 文件到 `.pi/sessions/`
- 跳过已存在的文件
- 验证文件完整性

## 7. 2026-06-05 运行时缺陷修复与预设系统优化

### 7.1 卡切换功能修复

**问题**: 前端 Web UI 切换角色卡不生效，始终停留在旧卡。

**根因**:
1. `rp-web-server.ts` 的 `activate_cards` handler 调用 `cardManager.activateCards()` —— 这是**追加**操作，不是替换。切两次后 active 列表变成 `["桃花村", "诡秘剧场"]`，`getActiveCardIds()[0]` 始终返回旧卡
2. `_preferredCardId` 模块变量只被 `/rp-use` 命令更新，前端切卡路径不更新它，而 `resolveCardId()` 优先看 `_preferredCardId`

**修复**:
| 文件 | 变更 |
|------|------|
| `src/rp-web-server.ts` | `activate_cards` handler 改用 `cardManager.setActiveCard()` 替换；新增 `setPreferredCard` 回调参数 |
| `.pi/extensions/rp-engine/index.ts` | 传入 `setPreferredCard` 回调，同步更新 `_preferredCardId` |

### 7.2 全局预设格式清理与结构整合

**问题**: `.pi/presets/1.md` 包含 HTML 实体 (`&#x20;`) 和 Markdown 转义字符 (`\#`, `\*`, `\-`, `\_`, `\.`)，干扰 AI 解析。

**清理内容**:
- `&#x20;` → 空格
- `\#` → `#`, `\*` → `*`, `\-` → `-`, `\_` → `_`, `\.` → `.`

**内部结构整合**:
- 去掉 `<wfeeling>` 冗余外壳标签
- `<writing_engine>` 只保留正向写作指导，`文风纠错` 移入 `<anti_cliche>`
- 独立 `铁律自检` 并入 `<anti_cliche>`（与句式黑名单去重）
- 最终结构：`<core_rules>` → `<writing_engine>` → `<user_boundary>` → `<anti_cliche>` (含 6 子章节) → `<metaphor_guidelines>` → `<nsfw_rule>` → `<pov>` → 剧情推进 → 字数限制

### 7.3 Pipeline 预算扩容

**问题**: 诡秘剧场角色卡的世界书+技能内容 (~132K 字节) 超出 `pipeline_target: 102400`，导致 rp-skills 被提取式摘要压缩（78,425 → 45,644，丢失 42%）。

**修复**: `.rpconfig.json`
```
pipeline_target: 102400 → 204800
pipeline_hard:   163840 → 245760
```

### 7.4 预设优先级强化

**问题**: 预设虽在 prompt 中（~16KB），但卡专属世界书内容 ~78KB，是预设的 4.6 倍。AI 自然倾向跟随更详细的卡专属指令，导致人称等关键规则被覆盖。

**修复**: `src/collectors/global-preset.ts` — 每个预设节点开头注入：
```
[引擎级全局预设 — 最高优先级，当与卡专属设定冲突时以此为准]
```
